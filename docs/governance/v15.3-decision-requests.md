# v15.3 Normative Decisions (Resolved Baseline)

Purpose: provide concrete decisions for v15.3 implementation and avoid ambiguity during thread handover.

Use this as the working baseline unless superseded by a new ADR update.

## 1) Guard semantics

Decision:
- Guard evaluation is exactly once per event per candidate transition.
- Transition objects must not be mutated during guard resolution.

Rationale:
- Prevents side effects and non-deterministic behavior.
- Matches expected pure-selection semantics for transition lookup.

Required code behavior:
- Resolve guard function to a local variable.
- Do not write resolved guard back to transition config objects.

Required tests:
- A guard with a counter should increment once per dispatched event.
- Repeated sends should not alter machine config object identity/content.

Required docs:
- Note non-mutation and single-evaluation rule in `docs/governance/fsmPlus-status-01.md`.

## 2) Transition action shape contract

Decision:
- Support both array and shorthand for `transition.actions`.
- Accepted input forms:
  - array of actions
  - single string
  - single function
  - single object descriptor
- Internal execution must normalize to array.

Rationale:
- Aligns better with XState-style ergonomics.
- Prevents current class of bugs where string is treated as iterable characters.

Required code behavior:
- Normalize with `toArray(transition.actions)` before action processing.
- Preserve current assign precedence semantics after normalization.

Required tests:
- `actions: 'log'` executes once (not per character).
- `actions: fn` executes once.
- `actions: { type: 'x' }` resolves and executes once.

Required docs:
- Update API examples in `projects/xstate-fsmPlus/README.md`.

## 3) ADR-0003 fail-fast validation scope

Decision:
- Fail fast at machine creation for structural config errors.
- Minimum enforced checks:
  - invalid machine/root `initial`
  - invalid compound `initial`
  - unknown transition target (for targeted transitions)
  - duplicate dot-path IDs

Rationale:
- ADR-0003 requires early validation and predictable runtime behavior.

Required code behavior:
- Throw `Error` in preprocessing with clear machine/state path context.

Required tests:
- One test per validation rule expecting throw at `createMachine(...)`.

Required docs:
- Add explicit validation list to `docs/governance/fsmPlus-status-01.md`.

Clarification:
- Until relative and `#id` target support is intentionally implemented, any unsupported or unknown target syntax hard-fails during preprocessing.
- This includes `#...` targets and relative targets in current scope.

## 4) ADR-0001 parallel-state enforcement

Decision:
- Reject `type: 'parallel'` at preprocess time, at any nesting depth.
- This is a hard fail until an ADR supersedes ADR-0001.

Rationale:
- ADR-0001 says parallel states are explicitly excluded.
- Fail-fast is clearer than silent unsupported behavior.

Required code behavior:
- During state traversal, if `stateConfig.type === 'parallel'`, throw.

Required tests:
- Root parallel config throws.
- Nested parallel config throws.

Required docs:
- Add explicit enforcement note in `docs/governance/fsmPlus-status-01.md`.

Duplicate-path collision clarification:
- Duplicate means any two state nodes that flatten to the same dot-path identifier.
- If keys containing dots (or any naming pattern) produce identical flattened paths, preprocessing must throw.

## 5) `state.changed` policy

Decision:
- Align with XState v4 intent:
  - targeted transition: `changed = true` when state value changes
  - targetless transition with executable actions: `changed = true`
  - no transition / no-op: `changed = false`

Rationale:
- Better parity for behavior-driven comparisons.
- Improves downstream observer correctness.

Required code behavior:
- Set `changed` from both state-value change and effective action execution.

Required tests:
- Targetless transition with actions returns `changed: true`.
- Unknown event returns `changed: false`.
- Targetless transition with only unresolved/non-executable action descriptors returns `changed: false`.

Required docs:
- Document `changed` semantics in engine status/backlog doc.

Clarification:
- `changed` is true for targetless transitions only when at least one action is effectively executable at runtime.
- Unresolved/non-executable action descriptors alone do not count as changed.

## 6) Testing strategy status text (truth runner)

Decision:
- Mark XState v4 truth runner as implemented baseline (not planned).
- Keep wording that additional scenario coverage is ongoing.

Required docs:
- Update `docs/governance/testing-strategy.md` wording from future/planned to active baseline where needed.

## 7) TRACE marker canonical form

Decision:
- Canonical trace delimiters are:
  - `TRACE BEGIN`
  - `TRACE END`

Rationale:
- Already used by suite helpers and diff tooling.

Required code behavior:
- Keep runner output and helper templates on this marker pair only.

Required docs:
- Ensure `tools/README_espruino.md` and strategy references use only this form.

## Implementation order for v15.3

1. Guard non-mutation + single-evaluation fix.
2. Action shape normalization.
3. ADR-0003 fail-fast validation checks.
4. ADR-0001 parallel rejection.
5. `state.changed` alignment update.
6. Tests and doc sync.
